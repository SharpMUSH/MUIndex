# Search and agent discoverability — 2026-09-09

Written from an SEOptimer audit of `mu-index.com` (9 September 2026, grade C, 19 recommendations),
a second report, and a set of directory-specific suggestions. This is the record of what was
changed, what was found that neither report mentioned, and — at least as important — what was
recommended and deliberately **not** done.

The site's own rules constrain this work more than they constrain most of the codebase. Several
standard SEO recommendations ask for exactly the thing this project exists to refuse: assert
something you have not measured, or claim something about a third party. Where that happened it is
recorded below with the reasoning, not quietly skipped.

## The two source reports

**SEOptimer.** Graded On-Page SEO B, GEO C+, Links F, Usability A+, Performance B+. Its findings
are specific and mostly correct. It audited the front page only, so several of its complaints turn
out to be site-wide rather than front-page-specific — which is how the largest finding below was
reached.

**Seobility.** The uploaded PDF is a single 612×792 page with **no text, no images and no font
resources** — 1.3 KB in total, an empty print. It contains nothing actionable and nothing from it
is used here. Worth re-exporting if its findings matter.

**Directory-specific suggestions** (schema on game pages, programmatic title templates, thin
content and category pages, a link-back badge). Two of these turned out to name real defects in
this repository rather than general advice, and are treated as findings below.

## What was actually wrong

Ordered by how much it mattered, not by which report raised it.

### 1. Every faceted listing declared itself a duplicate of `/games`

Not in either report. Found while checking the "keyword consistency" complaint.

`SiteUrls.CanonicalOf` drops the querystring. That is right, and its docstring gives the right
reason: the facet panel runs no script (spec §9), so it submits every control it has, and every
sort/exclusion/pair-of-filters combination is another URL. Left uncanonicalised that is an unbounded
supply of near-duplicates.

But it was applied to *every* listing URL, and swept up the ones that are not near-duplicates at
all. `/games?codebase=PennMUSH` answers a different question over a different set of rows than
`/games` does. Every one of those pages — the site's natural category pages, one per codebase,
lineage, genre, language and protocol — carried `/games`'s canonical link, `/games`'s title and
`/games`'s description. A search engine following its own rules would index none of them.

`IndexableFacet` draws the line: **one included value of one whitelisted dimension, at the default
sort, with nothing else asked** is a category and is self-canonical. Everything else — two facets,
an exclusion, the unknown token, a chosen sort, free text — stays consolidated onto `/games`. That
bounds the indexable set to roughly the *sum* of the dimensions' value counts rather than their
product.

Two details that are load-bearing:

- The rule reads the parsed `GameFilter`, not the querystring, so the legacy `?codebase-family=`
  spelling reaches the same answer and a parameter that selects nothing cannot disqualify a page.
- The value is respelled as the catalogue publishes it (`IndexableFacet.AsPublished`), so a
  hand-typed `?codebase=pennmush` canonicalizes onto the URL the panel links to rather than beside
  it — otherwise the fix would introduce the duplication it exists to remove.

`Band`, `LastSeen`, `Trending` and the two measurement switches are deliberately **not** indexable
dimensions: they read a measurement that moves, so the page behind such a URL holds a different set
of games next week.

### 2. The text mirror was an untitled duplicate of every page

Not in either report, though SEOptimer's crawl found the symptom — the first entry in its "Review
Child Pages" list is `/?plain=1`.

`?plain=1` is the same document at the same address (spec §9). The game page has always rendered
`SitePreview` above the plain/graphical switch. Every other page had it inside the graphical branch,
so the mirror came back with **no title, no description and no canonical link** — an
uncanonicalised twin of every page on the site, a few thousand of them.

Verified against production before changing anything: `/g/medievia?plain=1` carried a canonical,
`/`, `/games`, `/archive`, `/rankings`, `/ecosystem`, `/about` and `/crawler` did not.

`SitePreview` is now above the switch everywhere. `/crawler` had no metadata in *either* mode and
gained its own title and description.

### 3. The front page's title was eight characters

SEOptimer, medium priority. `<title>mu*index</title>` — the one page whose search result said what
the site is called and nothing about what it is.

`PreviewCopy.Title` answers the bare wordmark when a page supplies no title of its own, and the
front page supplied none. It now has one, translated into all four non-English locales rather than
falling back: German readers previously got the locale-neutral wordmark, and English prose would
have been a regression rather than an improvement.

Game page titles were the same shape — the game's name and nothing else, on a few thousand pages.
They now carry a clause describing the page. See "restraint" under §6 below for why the clause is
short and factual rather than the keyword-loaded template that was suggested.

### 4. Thin content and no heading depth on the front page

SEOptimer: 167 words, one `h1`, two `h2`, no `h3`.

The page was figures, feeds and a search box — legible to somebody who already knows what a MUCK is
and to nobody else. It gained four short passages (what a MU\* is; how the numbers are measured; the
three states of an hour; what the site will never have) and a described list of the nine surfaces it
previously reached only through one-word nav links. 197 → 513 words, and a real heading outline.

Two constraints shaped the copy:

- **No figure appears in it.** A number written into a message is a number nothing re-measures; the
  tiles above it are where counts belong.
- The promise about ranking is `rankings.noVote` — the rankings page's own sentence — rather than a
  second one saying the same thing. `PlainParityTests` bans the words "vote", "star" and "rating" on
  any surface as a proxy for "no affordance"; the guard now exempts exactly that sentence by id,
  with a companion test asserting the exemption still covers something, so the exemption cannot rot
  into a hole. ("Start here" was renamed for the same guard: it contains "star".)

The passages live in `HomeCopy` as ids, walked by both the page and its text mirror, so the two
cannot fall out of step.

### 5. No structured data outside game pages

SEOptimer flagged both "Add Schema Markup" and "Add Identity Schema". Three graphs were added.

**Identity** (`Organization` + `WebSite`), on every page. This one is **not** gated on the catalogue
being measured, unlike every other graph here — its subject is the site's own name, address, logo
and languages, all of which are as true over the demo fixture as over a live crawl. Suppressing it
would withhold a true statement rather than an invented one.

- `sameAs` is configuration (`SiteIdentityOptions`) and **ships empty**. It is the claim "that
  account over there is us", and a compiled-in default would have every fork assert it about
  somebody else's repository from its first deploy — the shape of mistake `ContactedMaintainer`
  already made once in this codebase.
- **No `SearchAction`.** Google announced the sitelinks searchbox's deprecation on 21 October 2024
  and retired it globally that November. Markup for it now describes a feature that cannot render.
  The rest of `WebSite` is still read, which is why the node stays.

**Listings** (`CollectionPage` + `ItemList`) on `/games`, its category pages and `/archive`. Capped
at thirty items: this is bytes on a page the same audit says loads slowly, and the per-game facts
belong on the game's own page. `numberOfItems` counts what is in the list, not what the query
matched, so it cannot be read as a total the list does not contain. No `itemListOrder` — the
vocabulary's ordering values describe rank, and rank is a word with a specific meaning here.

**Dataset** (`Dataset` + `DataCatalog`) on `/about/api`. This is the highest-value item in the whole
exercise and neither report raised it. The site already publishes everything that makes a dataset a
dataset — a bulk export in two formats, an OpenAPI contract, a configured licence, an attribution
string — and said so in no vocabulary a dataset index reads. Google Dataset Search is a separate
index with far less competition than web search, and a catalogue of a few thousand measured game
servers is squarely the kind of thing it exists to surface.

Deliberately absent from that graph: `temporalCoverage` and any row count. Both would be
measurements, and neither is one the page holds — the coverage of a catalogue that never retires a
host is open-ended at both ends, and a count written there is a number nothing re-measures.

### 6. Game pages did not publish where you connect

Raised in the directory-specific suggestions as "connectivity protocols (Telnet/SSH port) directly
in the metadata". Correct, and it was in the preview description but nowhere a program could read it
as an address. `GameStructuredData` now emits a `GameServer` node carrying `telnet://host:port`
(a registered URI scheme, RFC 4248).

**It carries no `serverStatus` and no `playersOnline`, and those omissions are the rule rather than
oversights.** `GameServerStatus` offers Online and Offline; this graph has nowhere to say "as of
when" about either. That is the same gap that already forces the player count to travel on an
`InteractionCounter` with an `endTime`. And an undated "Offline" would state our vantage point as a
fact about somebody's game — a game we cannot route to is unreachable and perfectly alive, which is
why this project says reachable and never up (rule 5). `dateModified` already carries when we last
got in.

**On the suggested title template — restraint, deliberately.** The proposed shape was
`LuminariMUD - Live MU* Status, Player Count, and Connection Info | mu*index`. Three problems: "Live
status" is an unmeasured claim; "Player Count" promises a number that is unknown for a large part of
the catalogue; and a fixed keyword-loaded suffix repeated across a few thousand pages is the textbook
input to Google's title rewriting, which would discard it. The clause actually shipped —
`{game}: how to connect, and what we measured` — describes *this page*, stays true of an archived
game and of one we hold no count for, and puts the name first so a truncated title keeps the half
that identifies it.

It is also gated on the locale having its own translation, which is unusual in this codebase and
deliberate: everywhere else an untranslated string falls back to English because the alternative is
no string at all. Here the alternative is the game's own name — machine voice, correct in every
language — so a locale without a translation keeps that rather than being handed an English clause.

### 7. `llms.txt`

SEOptimer, low priority, GEO. Added, and **not published as a ranking signal**, because the evidence
says it is not one: Google's position is that no Search system reads it; no major model provider
documents it as a citation input; an analysis of 137,000 sites in 2026 found the overwhelming
majority of these files were never fetched.

It is here because the thing it is *for* is true of this site independently. There is a plain-text
rendering of every page and a documented, versioned JSON API, and an agent that finds either gets a
better answer with less of somebody's bandwidth than one parsing HTML. It also states the four rules
an agent most often gets wrong about this data — measured vs declared, reachable never uptime, the
three states of an hour, and no absolute population total — which is worth having whether or not the
convention survives. The licence is read from configuration, so the file cannot claim terms the dump
does not go out under, and over the fixture it says so in its first line.

English only, deliberately: it addresses a program, and a translated copy at one fixed address would
have to pick a language anyway.

### 8. Crawl directives

- `/find` and `/crawler` are in the header and were in no sitemap.
- The category listings are now submitted, taken from the same facet pass the panel draws. A test
  walks every submitted category and asserts it is self-canonical — submitting a page that names
  another as its canonical is a contradiction.
- `robots.txt` excludes `/g/*/claim`. Signed out that is one short "you need an account first"
  repeated under every slug; it is excluded on the same ground `/account` is, because it belongs to
  whoever is signed in, not as a crawl-budget trim. The game's own page is unaffected.

### 9. Two defects found in passing

**The badge snippet did not work.** The owner dashboard's copy-paste markup used rooted paths
(`/g/slug`), so pasted on an operator's own site it linked to a page of *theirs* that does not exist
and loaded no image. That is the one feature in the repository whose entire purpose is a link back
here, and it had been broken for everybody who used it. Now absolute.

**The badge was reachable only after signing in and claiming**, which is the wrong way round: an
operator deciding whether this catalogue is worth linking to is reading the game's public page, not
an account they have not made. It is now offered there too, folded shut, for every listed game. The
badge endpoint was already public and publishes nothing the page does not already show.

This is the only reader-visible product change in the work, and the only on-site lever on the
audit's single high-priority item. It is easy to drop if unwanted.

## What was recommended and not done

### Analytics

SEOptimer, low priority: "We could not detect an analytics tool installed on your page."

**Declined.** This site runs no script at all — the facet panel and the plain surface depend on that,
and `App.razor` documents the choice. An analytics tag would send every reader's address to a third
party in exchange for numbers nobody asked for, on a site whose `IconFetcher` exists specifically so
that a *decoration* does not do that (§11). If traffic data is wanted later, server-side aggregates
from the existing request metrics are the shape that fits.

### A Facebook pixel

**Declined**, and more firmly. A retargeting pixel is the analytics objection plus an advertising
identity graph.

### Address, phone number, and LocalBusiness schema

SEOptimer, low priority, twice. **Declined as inapplicable.** MUIndex is not a local business and has
no premises. The audit itself reports a phone number of `+1 22998824749`, which is not a phone
number; it appears to have parsed a hostname or port out of the page. Publishing an address and
`LocalBusiness` markup to satisfy this check would mean inventing both.

### Facebook, X, Instagram, YouTube and LinkedIn profiles

SEOptimer, five separate low-priority items. **Declined as a code change.** These are not things a
pull request can create. The mechanism to link them once they exist has been added — `Site:SameAs`
feeds the `Organization` node's `sameAs` — and it ships empty precisely so that nobody's account is
claimed by default.

### "Vote for us" anchor text on the link-back badge

From the directory-specific suggestions. **Declined outright.** A vote affordance is permanently
ruled out (§2 of the project's own rules — it is the thing that reduced Top Mud Sites to a link
graveyard), and anchor text soliciting one would import the incentive the ban exists to remove. The
badge links back with the game's own name.

### hreflang in the sitemap

Considered, **not done**. Google accepts either HTML `link rel="alternate"` elements or `xhtml:link`
entries in the sitemap, and the consistent advice is to pick one and not mix them for the same URLs.
This site already emits correct HTML alternates including a self-reference and `x-default`. Adding
sitemap annotations would be a second, conflicting signal for no gain.

### Improving page load speed

SEOptimer, medium priority: 0.909 s server response, 1.1 s to loaded.

**Investigated, not changed.** The dominant cost is that every HTML document is answered
`Cache-Control: no-store`, so nothing is cached at the edge. That is deliberate and
`PageCacheHeaders` documents why: a page from this site is an answer about one signed-in reader at
one moment, and without the directive a reader who signed in and pressed Back was handed the
signed-out render, reproducibly, in both Chromium and Firefox. Splitting anonymous from
authenticated caching is a real improvement and a real change to that guarantee — it deserves its
own change with its own reasoning, not a line in an SEO pass.

Worth noting the added markup pushes the other way slightly, which is why the `ItemList` is capped
at thirty items rather than the hundred a listing draws.

### Link building

SEOptimer's only high-priority item: 3 backlinks, 3 referring domains.

**Nothing in a pull request fixes this**, and it is worth being plain about that rather than
shipping something that looks like it does. What the code can do has been done — the badge works and
is now discoverable by the operators best placed to use it. The rest is outreach, and the honest
version of the suggestion is: the games in this catalogue are the natural source of links, the badge
is the artefact to offer them, and it earns a link by being useful (a live player count on their own
front page) rather than by asking for a vote.

## Translation status

New surface ships English-only where it has no translation, which is consistent with the site's
existing state — `/about` is entirely English in German today, and 388 strings were already recorded
as identical in English and German in the 2026-08-17 sweep. Two strings were translated into all
four locales rather than left to fall back, because for those the fallback would have been a
*regression* from a locale-neutral value:

- `preview.title.home` — translated. Without it, a German front page's `<title>` would go from the
  neutral wordmark to English prose.
- `preview.title.game` — gated on `Messages.HasOwn` instead. The fallback there is the game's own
  name, which is correct in every language.

Left for a translator: the category titles, headings and descriptions
(`preview.title.category.*`, `preview.desc.category.*`, `games.heading.*`), the front page's four
passages and start list (`home.what.*` through `home.start.*`), `/crawler`'s title and description,
and the two badge strings.
